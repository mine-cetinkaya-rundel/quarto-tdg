2  Your Quarto workflow

You do not need a specific tool to author and render Quarto documents. You can author Quarto documents in any plain text editor and render them with the quarto render command in your computer’s terminal.

However, we recommend using an integrated development environment (IDE) when working with Quarto for features like preview and live rendering that let you see how your content will look as you write, syntax highlighting, project management, version control integration, debugging tools, and efficiency and productivity features such as snippets, templates, and keyboard shortcuts. Additionally, most modern IDEs offer intelligent code assistance, auto-completion, and error highlighting, which can help you quickly find the right syntax and catch errors.

In this chapter, you’ll learn how to render and preview Quarto documents from the command line, how Quarto executes R and Python code, how Positron and RStudio support interactive authoring, and how to choose the right tool for your workflow. We detail how to use Positron and RStudio with Quarto, as well as briefly introduce other tools you might use for Quarto authoring. We spend more time on Positron than on RStudio because RStudio’s Quarto support is mature and well documented elsewhere, whereas Positron is newer and its Quarto features are less widely covered.

2.1 Document structure

Quarto documents are plain-text files that use Markdown for formatting and can include executable code cells. They have the file extension .qmd and can be rendered to various output formats, including HTML, PDF, Word documents, and more. They comprise three main components: a YAML header for metadata, markdown text for content, and code cells for executable code.

  1. YAML header: Metadata enclosed by --- markers, including the title, format, theme, and other document options.
  2. Markdown text: Formatted text using standard Markdown syntax for headings, lists, links, emphasis, and more.
  3. Code cells: Executable code cells marked with ```{r} or ```{python} that can include optional cell options to control execution and output.

2.2 Quarto CLI

Before diving into specific IDEs, let’s start with the fundamentals: the Quarto Command Line Interface (CLI). The Quarto CLI is the core tool that powers all Quarto rendering, regardless of which editor you use.

When you are getting started, you only need a small set of commands for most Quarto work:

quarto preview document.qmd
quarto render document.qmd
quarto check

Use quarto preview while you are actively writing. Preview renders your document, opens the result, and keeps watching for changes. Each time you save the source file, Quarto updates the preview so you can see the effect of your edits.

Use quarto render to produce the final output file. Rendering creates the output once and then stops. This is the command you will typically use when you are ready to share or publish a document.

Use quarto check when you first install Quarto or when something is not rendering as expected. It verifies that Quarto and its supporting tools, such as knitr, Jupyter, and LaTeX, are available on your system.

The same basic workflow applies whether you work from the terminal or from an IDE. IDEs such as Positron, RStudio, and VS Code provide buttons, keyboard shortcuts, and preview panes for these tasks, but the underlying Quarto workflow is the same.

2.2.1 Rendering

The most fundamental Quarto command is quarto render, which converts your Quarto document into the desired output format. Quarto uses the term render to describe the process of taking this source document and producing a new file that combines the output from the executed code cells with the Markdown. You can render a specific Quarto document in the Terminal with:

quarto render document.qmd

Alternatively, you can render all Quarto documents in the current directory with:

quarto render

By default, Quarto will render your document in the format specified in the YAML header, falling back to HTML if none is specified. You can override the output format using the --to option:

quarto render document.qmd --to pdf
quarto render document.qmd --to docx

2.2.2 Previewing

While quarto render creates the output file and stops, quarto preview renders your document, opens it in your web browser, and automatically re-renders when you save changes to the source file:

quarto preview document.qmd

This command is particularly useful during active authoring, as it lets you see your changes immediately without having to manually rerun the render command. The preview server will continue running until you stop it (typically with Ctrl+C in the Terminal).

Preview isn’t limited to single documents: run quarto preview in a project directory—such as a website or book—and Quarto serves the whole project, refreshing whichever pages you edit.

2.2.3 Other useful commands

Beyond rendering and previewing, the Quarto CLI offers several other helpful commands.

To see which version of Quarto you have installed, run:

quarto --version

When your document is ready to share, quarto publish can render and push it to a variety of destinations, including GitHub Pages, Posit Connect, and Posit Connect Cloud:

quarto publish document.qmd

To get help, you can use the following command:

quarto --help

Or you can use --help with any command to see available options and usage information.

quarto render --help

2.3 Computation engines

Quarto delegates the execution of your code to a computation engine—knitr for R and Jupyter for Python (and other languages with Jupyter kernels). The concepts in this section apply no matter which editor you use, so we cover them here before turning to specific IDEs.

A quick note on terminology: knitr and R Markdown traditionally call a block of executable code a chunk, while Jupyter calls it a cell. Quarto’s documentation—and this book—use cell, but you’ll see both terms in the wild, and they mean the same thing.

2.3.1 Knitr engine

Quarto is designed to be highly compatible with existing R Markdown documents—you can generally render an existing .Rmd file with Quarto without any changes.

The main difference to be aware of is how cell options are specified. In Quarto, cell options are typically written as special comments at the top of the cell using the #| prefix, rather than on the line that opens the cell:

```{r}
#| echo: false
#| fig-cap: "Air Quality"
library(ggplot2)
ggplot(airquality, aes(Temp, Ozone)) +
  geom_point() +
  geom_smooth(method = "loess", se = FALSE)
```

This makes it easier to work with longer options like fig-cap, fig-subcap, and fig-alt, and to edit cell options in structured editors such as notebooks. Since options use YAML syntax rather than R syntax, when you need an R expression for a value, you need to prefix it with !expr:

#| fig-cap: !expr 'paste("Air", "Quality")'

2.3.2 Jupyter engine

To execute Python code, Quarto documents use the Jupyter engine. These documents include a jupyter option in the YAML front matter that specifies the kernel to use:

---
title: Matplotlib Demo
author: Norah Smith
jupyter: python3
---

One execution behavior worth remembering: when you render a .qmd file, Quarto always executes its cells, but when you render an .ipynb notebook, Quarto does not execute cells by default—it assumes you already ran them while editing. We return to this asymmetry when discussing notebook editing in Positron (Section 2.4).

Now that you understand the foundational CLI commands and how Quarto executes code, let’s explore how different IDEs integrate these capabilities into their interfaces to support your authoring experience.

2.4 Positron

Positron is a next-generation data science IDE that comes pre-configured for Quarto—the Quarto CLI is built in, and the Quarto VS Code extension is bundled. Additionally, Positron offers specialized features for Quarto authoring, such as integrated rendering and preview for Quarto documents, completion and diagnostics for Quarto options, and full R and Python support for code that is inside code cells in a Quarto document, including interactive execution of code in the Console, code completion, help, and diagnostics.

2.4.1 Installation

To get started with Quarto in Positron, download and install Positron from positron.posit.co. Since Quarto is built into Positron, no additional installation is required. Depending on your language of choice, you’ll also need to have R or Python installed on your system—R from cran.r-project.org or Python from python.org.

Positron’s Quarto support comes from the bundled Quarto extension, which is included as a bootstrapped extension—it behaves just as if you had installed it yourself, updates automatically as new versions appear in the extension gallery, and can be uninstalled if you ever need to.

2.4.2 Managing Quarto installations

Positron ships with its own copy of the Quarto CLI, but you aren’t locked into it. If you’d prefer to use a version of Quarto that you’ve installed yourself—say, to match the version your project uses elsewhere—that generally works automatically. When you need finer control over exactly which Quarto is used, set the quarto.path setting to point at the installation you want.

To see which version is currently active, check Positron’s bottom status bar. After changing your Quarto version, restart Positron so the status bar updates.

2.4.3 Core features

Positron provides several features that make Quarto authoring efficient and productive. Here’s an overview; the subsections that follow cover each in more depth:

  • Previewing: render .qmd files and view the result side by side with your source, using the Quarto: Preview command, the keyboard shortcut (⇧⌘K on macOS, Ctrl+Shift+K on Windows/Linux), or the Preview button in the toolbar.

  • Dual editor modes: switch between source and visual editing (see Visual editor).

  • Polyglot language support: first-class support for R and Python makes Positron an excellent choice for Quarto projects with computational cells in either language or both languages.

  • Interactive code execution: run individual code cells in the Console without rendering the entire document (see Running code cells).

  • Code completion and diagnostics: as you type, Positron suggests valid Quarto and YAML options and flags syntax errors, helping you catch problems before you render.

Note that for executing code cells in Quarto documents in Positron, you’ll need to install some packages depending on your language of choice.

  • For R, you need the knitr package:
install.packages("knitr")
  • For Python, you need the jupyter package:
pip install jupyter

2.4.4 Basic workflow

The typical workflow for authoring Quarto documents in Positron follows these steps:

  1. Create or open a .qmd file in the Editor pane.
  2. Preview your document by executing the Quarto: Preview command to render and display the output.
  3. Iterate on your content by making edits and re-running the preview. You can optionally enable Render on Save to automatically update the preview whenever you save your file.
  4. Execute code interactively by running individual code cells using the Run Cell button, which allows you to test your code without rendering the entire document.

2.4.5 Visual editor

The dual editor modes noted above give you access to Positron’s visual editor, a WYSIWYM (“what you see is what you mean”) interface for editing Quarto markdown without working directly in the source. Use the Edit in Visual Mode / Edit in Source Mode commands or the keyboard shortcut (⇧⌘F4 on macOS, Ctrl+Shift+F4 on Windows/Linux) to switch between modes. Beyond basic formatting, it supports many of Quarto’s richer constructs, including tables, citations, cross-references, footnotes, divs and spans, definition lists, attributes, and raw HTML or LaTeX. The visual editor’s support is still somewhat limited in Positron, though: it’s a great fit for rich-text authoring, but running code and other language features aren’t available in visual mode, so switch to source mode when you need them. We keep the coverage brief here and highlight visual-editor features throughout the book where they’re relevant.

2.4.6 Editing notebooks

In addition to the source and visual editors for .qmd files, Positron includes a Notebook Editor for authoring Jupyter notebooks (.ipynb) that are rendered with Quarto. This is a natural fit if you already work in notebooks or prefer a cell-based interface.

Editing an .ipynb for Quarto differs from a .qmd file in a few ways:

  • YAML front matter goes in the first cell, which should be a Raw cell containing the title, author, and any other document options. Use the cell type menu at the bottom right of a cell to switch it to Raw.

  • Markdown cells accept any valid Pandoc markdown, including Quarto features such as cross-references.

  • Cell options use the same #| comment prefix as .qmd files and must appear at the very start of the cell.

Rendering and preview work just as they do for .qmd files: run the Quarto: Preview command once, and the preview refreshes each time you save. One key difference is execution—as noted in Section 2.3, .qmd files are always executed when rendered, but when rendering an .ipynb, Quarto does not run the cells by default, assuming you’ve already executed them while editing. To execute cells during rendering, pass the --execute flag:

quarto render notebook.ipynb --execute

or enable it in the notebook’s YAML front matter:

execute:
  enabled: true

You can convert between .qmd and .ipynb representations at any time with quarto convert:

quarto convert notebook.ipynb
quarto convert notebook.qmd

2.4.7 Running code cells

The interactive execution introduced above is supported by a full set of commands to run R, Python, and Julia cells, with output appearing in the Console. You can run the current cell, the next or previous cell, all cells, the cells above or below the cursor, or just the selected line(s):

Command macOS Windows/Linux
Run Current Cell ⇧⌘Enter Ctrl+Shift+Enter
Run Selected Line(s) ⌘Enter Ctrl+Enter
Run Next Cell ⌥⌘N Ctrl+Alt+N
Run Previous Cell ⌥⌘P Ctrl+Alt+P
Run All Cells ⌥⌘R Ctrl+Alt+R
Run Cells Above ⇧⌥⌘P Ctrl+Shift+Alt+P
Run Cells Below ⇧⌥⌘N Ctrl+Shift+Alt+N

You can insert a new code cell with ⇧⌘I (Ctrl+Shift+I on Windows/Linux). Enhanced features like completion and execution are built in for R and Python cells; for Julia, install the Julia extension to enable them.

2.4.8 Inline output

By default, running a code cell sends it to the Console, as described above. Positron can instead display cell output inline, directly beneath each cell in the source editor—much like a Jupyter notebook or RStudio’s R Notebooks. To use this feature, you must first enable it in your user or workspace settings.

Turning on inline output also changes the execution model. Rather than sharing a single Console across every document, Positron gives each .qmd file its own isolated R or Python session.

2.4.9 Contextual assistance

While you edit R and Python code cells, Positron offers the same assistance you’d get in a script or the Console: completion for functions and their arguments, help tooltips as you type or hover over a function, and full documentation in the Help pane when you press F1 with the cursor in a function.

For assistance with the prose and math around your code, run the Quarto: Show Assist Panel command to open a panel in the sidebar that updates based on where your cursor is. It shows a preview of LaTeX math as you edit an equation, and a thumbnail preview when your cursor is on a markdown image—handy for confirming you’ve referenced the right file.

2.4.10 Live preview

When you’re writing LaTeX math or a Mermaid or Graphviz diagram, you can open a live preview that re-renders automatically as you type. Click the Preview button above the code block, or use the ⇧⌘L shortcut (Ctrl+Shift+L on Windows/Linux). The preview appears in the Quarto assist panel alongside your document, so you can catch mistakes in an equation or diagram without rendering the whole file.

2.4.11 Previewing and rendering other formats

The Quarto: Preview command renders and previews your document’s default format. To preview a different format, use the Quarto: Preview Format command, which offers a list of formats to choose from—those declared in the document plus standard options like PDF and MS Word. After you preview a different format, Quarto: Preview and its keyboard shortcut rebind to that format for the duration of the preview; run Quarto: Preview Format again to switch back.

Embedded, side-by-side preview is available for HTML- and PDF-based formats, including revealjs and beamer slides. For Word and other formats, Positron renders the file, but you’ll open it in an external application to view the result.

Because preview renders only one format at a time, use the Quarto: Render Document command when a document declares multiple formats and you want to produce all of them. This command lets you render all declared formats at once, or selectively render any declared or standard format, such as PDF or MS Word.

2.4.12 Render on Save

By default, Positron does not re-render your document every time you save—rendering can be slow if it involves long-running computations, and it’s useful to be able to save freely without triggering a full render. When you do want automatic rendering, you have three ways to enable Render on Save:

  1. Check the Render on Save box in the editor toolbar for the current document.
  2. Search for quarto.render in settings and enable the Render on Save option to make it the default for all documents.
  3. Set the editor option in your front matter (or project _quarto.yml), which overrides the Positron setting:
editor:
  render-on-save: true

With Render on Save enabled, the preview refreshes automatically each time you save.

2.4.13 External preview

By default, the rendered preview opens in a side-by-side panel inside Positron. If you’d rather preview in an external browser—or suppress the automatic preview entirely—change the Preview Type setting. Search for quarto preview type in user or workspace settings to find Quarto > Render: Preview Type, which offers three choices: internal (the default side-by-side panel), external (open in your default browser), and none (render without opening a preview).

2.5 RStudio

RStudio is an IDE specifically designed for R, and it provides excellent support for Quarto authoring. RStudio comes with Quarto pre-installed and provides a rich set of features that make it easy to create, edit, and render Quarto documents, including syntax highlighting, code completion, integrated rendering and preview, and support for both visual and source editing modes.

2.5.1 Installation

To get started with Quarto in RStudio, download and install the latest version of RStudio from posit.co/download/rstudio-desktop. Also make sure that you have R installed on your system, which you can get from cran.r-project.org.

2.5.2 Creating documents

To create a new Quarto document in RStudio, use the File > New File > Quarto Document… command. This opens the New Quarto Document dialog, where you can give the document a title and author and choose a default output format before RStudio creates a ready-to-edit .qmd file.

2.5.5 Projects

To create a project for a Quarto document or a set of related documents, use the File > New Project… command, choose New Directory, and then select Quarto Project.

The New Project wizard can create plain document projects as well as websites and books. It also provides options to initialize a git repository and set up an renv environment, which help make your project reproducible from the start.

2.5.6 Python environments

You can author Quarto documents that use the Jupyter engine (Section 2.3) in RStudio, for example to execute Python code. To work within a Python virtual environment (venv), use the File > New Project… command, choose the Jupyter engine, and specify the packages you’d like to seed the environment with. RStudio then activates this environment automatically whenever you open the project. You can install additional packages later from the RStudio Terminal tab, for example:

python3 -m pip install scikit-learn

2.5.7 YAML intelligence

RStudio provides code completion for the YAML you write in Quarto documents, covering project files, the document’s YAML front matter, and executable cell options. As you type, it suggests valid keys and values, which helps you discover options and avoid typos. If your YAML is invalid, RStudio also flags it when you save the document, underlining the problem so you can fix it before rendering.

2.6 Other tools

While Positron and RStudio offer rich, integrated experiences for Quarto authoring, you can use Quarto with many other tools depending on your preferences and workflow.

2.6.1 VS Code

Visual Studio Code with the Quarto extension provides excellent support for authoring Quarto documents. The extension offers preview, syntax highlighting, code completion, and integrated terminal access. VS Code is particularly popular among Python developers and those who work across multiple programming languages.

To get started with VS Code, first install VS Code from code.visualstudio.com. Then install the Quarto CLI from quarto.org and the Quarto extension from the VS Code Marketplace.

Similar to Positron and RStudio, you can preview documents with the keyboard shortcut ⇧⌘K (Ctrl+Shift+K on Windows/Linux) and run individual code cells with ⇧⌘Enter (Ctrl+Shift+Enter on Windows/Linux).

2.6.2 JupyterLab

If you’re already working with Jupyter notebooks (.ipynb files), you can use Quarto to render them to various output formats. JupyterLab provides an interactive environment for working with notebooks, and the Quarto CLI can render these notebooks just as it renders .qmd files.

You can also work with .qmd files directly in JupyterLab by installing the Quarto extension, which offers preview and rendering capabilities within the JupyterLab interface.

2.6.3 Neovim and Vim

For developers who prefer terminal-based editors, both Neovim and Vim can be configured to work with Quarto documents. Community-developed plugins provide features like syntax highlighting, code execution, and preview integration.

2.6.4 Other editors

Since Quarto documents are plain text files, you can author them in virtually any text editor:

  • Emacs: With Markdown mode and language-specific modes (ESS for R, python-mode, etc.).
  • Sublime Text: Using Markdown packages and build systems.
  • Zed: With Markdown support and terminal integration.
  • Any plain text editor: You can always author in your favorite editor and use quarto render from the command line.

2.7 Choosing a tool

The best tool for Quarto authoring depends on your specific needs and existing workflow:

  • If you primarily work with R, RStudio provides the most integrated experience with excellent support for R-specific features.

  • If you’re working with multiple languages, Jupyter notebooks, or prefer a modern IDE, Positron offers a rich set of features, with strong support for both R and Python.

  • If you already use VS Code for development, adding the Quarto extension gives you powerful Quarto capabilities in your familiar environment.

  • If your workflow is notebook-first, JupyterLab lets you keep authoring in .ipynb files and render them with Quarto, with optional .qmd support via the Quarto extension.

  • If you prefer keyboard-driven, terminal-based workflows, editors like Neovim or Vim can be configured to work effectively with Quarto.

Whichever editor you choose, the core Quarto workflow is the same: write plain-text source, preview as you develop, render to produce the final output, and use projects/environments to make the work reproducible.
